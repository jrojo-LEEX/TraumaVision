Qué hace

{{ app_name }} es un prototipo académico de soporte a la decisión clínica, desarrollado como Proyecto Integrador de Ingeniería Biomédica (UNC). Usa un único modelo de detección, {{ modelo }} (YOLOv8m, una sola clase: «fractura»), que señala en radiografías de muñeca pediátrica las zonas con patrones compatibles con fractura.

Cada proyección se analiza por separado: el modelo no combina las vistas entre sí. En un estudio de varias imágenes, la urgencia del estudio es la de su proyección más urgente. {% if clahe %}Antes del análisis, cada imagen se preprocesa con CLAHE (límite {{ coma(clahe.clip, 1) }}, grilla {{ clahe.grilla }}×{{ clahe.grilla }}), igual que en el entrenamiento.{% endif %}

El resultado se puede descargar como informe PDF y, si el servidor tiene configurado el correo, enviar por mail. No hay una API pública: el sistema se usa sólo desde esta interfaz, con sesión iniciada.

No emite diagnósticos. Todo resultado debe ser interpretado, validado y aprobado por un médico matriculado.

Limitaciones conocidas

  • Dominio acotado. El modelo se entrenó con GRAZPEDWRI-DX, partido por paciente: radiografías de muñeca de pacientes de 0 a 19 años. Fuera de esa región y ese rango etario su comportamiento no está validado. Si en la base quedan análisis hechos con un modelo anterior, se muestran marcados como «modelo anterior», sin prioridad clínica, y no entran en las métricas.
  • El puntaje del detector no es una probabilidad. El número que acompaña a cada zona marcada (la «seguridad» del detector) es su score crudo post-NMS: sirve para ordenar las detecciones, pero no es una probabilidad de fractura. El modelo no se calibró, así que ese número no debe leerse como tal.
  • Los cortes son operativos. Con un score de {{ coma(umbrales.hallazgo) }} o más la imagen se clasifica con hallazgos («Revisar»); ese corte se eligió sobre la partición de validación. Con {{ coma(umbrales.prioritario) }} o más pasa a «Prioritario». Entre {{ coma(umbrales.caja) }} y {{ coma(umbrales.hallazgo) }} la zona se dibuja con una caja punteada («Límite»), sin clasificar la imagen como anormal. Los cortes ordenan la revisión; no reemplazan el criterio clínico.
  • Un negativo no descarta fractura. {% if meta and meta.sensibilidad is not none %} En el test interno, con el corte de {{ coma(umbrales.hallazgo) }}, no se clasificaron con hallazgos {{ miles(meta.test_FN) }} de las {{ miles(meta.test_n_positivos) }} radiografías con fractura (sensibilidad por imagen {{ pct(meta.sensibilidad) }}): alrededor de {{ ((1 - meta.sensibilidad) * 100)|round|int }} de cada 100 radiografías con fractura no se marcaron. {% else %} El modelo en uso no tiene métricas publicadas en este sistema, así que esta página no informa ninguna tasa de detección. {% endif %} Por eso un resultado sin hallazgos nunca se presenta como un resultado normal confirmado.

Datos de los estudios

Las imágenes DICOM se convierten a PNG sin sus metadatos (los datos del paciente no se usan ni se guardan), y cada imagen se guarda con un nombre aleatorio. En los estudios ZIP, los nombres de las imágenes se guardan con los números largos tapados; el nombre del ZIP se guarda tal como se subió. Cada usuario accede sólo a sus propios estudios. El informe PDF incluye las imágenes: si se manda por mail, sale del sistema.

Aun así, esta es una instalación de demostración: no debe utilizarse con estudios de pacientes reales identificables.
